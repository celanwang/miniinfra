# 并发事务与语句快照

事务管理器拥有事务状态和已发布视图，锁管理器裁决写冲突。数据页刷盘、提交记录落盘和对读者可见各有自己的时点。

## 一条语句的读写顺序

1. 普通查询开始时取得并登记一个已发布视图，语句结束时注销。登记必须与后台取得回收界限协调，保证刚取得的快照仍能读到旧版本。
2. 写语句先取得候选行身份，再申请逻辑行写锁。唯一约束按索引标识和规范化键值仲裁。等待者让出执行名额，取得锁后重查最新状态。已提交、已中止和仍在执行三种状态分别处理。
3. 同一事务可读取自己先前语句的修改。其他事务只按各自语句的快照读取。事务发布后启动的新查询看见整笔变更，已经开始的查询沿用原视图。
4. 事务在死锁或锁等待超时时整笔中止，唤醒受影响的等待者。已经进入不可撤销提交路径的事务不能再被选作死锁牺牲者。

## 并行事务何时可见

建议为已发布的事务提供单调的提交序号，或提供能表示同一视图的活动事务集合。仅凭事务开始时取得的递增编号无法区分先开始、后提交的事务。评审时应明确哪份状态负责判定可见性，检查点如何恢复它，以及何时能回收事务状态。

两个事务争同一个从未出现的请求号时也要排队。持有者中止，等待者可继续。持有者提交，等待者重查后得到唯一冲突。热点等待上限的作用是约束挂起成本。测试时也要计入已持锁的多行事务、连接和等待队列占用，单纯释放执行名额不能释放这些资源。 [唯一索引的并发检查](https://www.postgresql.org/docs/current/index-unique-checks.html)

**验收。** 让先开始的事务后提交，在两次提交之间启动联接查询，验证快照只包含当时已发布的订单。在混合热点与普通订单的负载下分别记录锁等待、WAL 同步耗时和去重后的有效提交数。

## 当前事务状态

事务提交序号按 WAL 发布顺序分配。每条普通语句固定一个已发布序号，执行器在该视图上叠加本事务的修改。中止事务的版本不取得提交序号。逐行锁和唯一键锁持有至提交发布或回滚。锁等待由等待图检测，达到等待期限或发现环时整笔中止。
