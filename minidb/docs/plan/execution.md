# 会话与 SQL 执行

一个连接对应一个会话。会话持有当前事务和请求状态。执行器向事务管理器申请语句快照，再把同一份快照传给扫描、过滤、索引回表和联接。网络回包、客户端取消与数据库提交是三个独立事件。

## 一笔订单经过哪些接口

| 请求 | 执行器与内核的交接 | 客户端看到什么 |
| --- | --- | --- |
| 插入带唯一请求号的订单 | 绑定表和索引，交给写入路径仲裁唯一键。 | 语句成功或唯一冲突。提交前仍可整笔回滚。 |
| 条件扣减库存 | 走主键索引定位候选。写锁等待结束后重查同一行的库存条件。 | 返回受影响行数。零行也是正常 SQL 结果，由订单应用决定回滚。 |
| 查询订单和明细 | 主键扫描、二级索引回表和联接都用本语句的视图，叠加本事务先前的写入。 | 同一查询只能看到整笔订单的一个已发布状态。 |
| 提交订单 | 把提交交给事务管理器，等待发布，再通过连接返回。 | 已提交、已中止，或断线导致结果未知。 |

端到端验收只需要建表及主键、唯一索引、显式事务、插入、条件更新和等值联接。顺序扫描与索引扫描应返回相同的可见行。若列类型或表达式尚不能执行，在规划时返回明确错误。查询计划不应改变事务可见性。 [PostgreSQL 的更新计数](https://www.postgresql.org/docs/current/sql-update.html#SQL-UPDATE-OUTPUTS)

## 断线与重试

服务端在执行 SQL 的同时继续读取 TCP。普通 EOF 允许客户端关闭写方向后继续读取最后一条回应。服务端处理完已收到的请求后结束会话。Go 驱动因取消而中止已在途的请求时，尝试用 TCP reset 关闭连接。服务端读到传输错误后取消会话上下文，等待行锁的语句随即醒来，由原执行线程回滚未提交的更改并释放锁。若服务端只收到 FIN，或网络故障尚未被感知，锁等待和语句超时仍是执行边界。

| 客户端遇到的情况 | 事务状态与客户端动作 |
| --- | --- |
| 语句发送前已取消 | 该语句未执行。若只取消语句自身的上下文，已有显式事务仍可继续。取消 `BeginTx` 使用的上下文时，由 `database/sql` 结束事务。 |
| 显式事务内取消正在收发的语句，尚未发出 `COMMIT` | 驱动返回 `context.Canceled` 或 `context.DeadlineExceeded` 并丢弃连接。结束原事务，从连接池重新获取会话，通过原请求号重试整笔订单。 |
| 可能已发出 `COMMIT` 或自动提交写入，请求未收到有效回包 | 驱动返回 `client.CommitUnknown`。持久化路径已接手的提交由内核完成裁决。驱动将结果留给应用核对，避免 `database/sql` 自动重放写入。 |

用原请求号和摘要核对未知结果。查到同一请求号和摘要时复用结果，摘要不同则报告冲突。若暂时查不到，仍用原请求号重试，让唯一键裁决与原事务的竞争。订单行、扣减和明细在同一事务提交，唯一键冲突后回滚本次尝试。

### 并发订单验证

A 锁住商品 1。B 插入带唯一请求号的订单和一条明细，预占商品 2，随后等待 A。取消 B 的等待语句，记录应用返回错误和另一客户端 C 在商品 2 上完成更新的时间。A 保持原锁到 C 完成。另一个连接同时完成商品 3 的同步更新。

Apple M4 Max 本机 TCP 下，带竞态检测，基线 `934686e` 加探针跑三轮。取消到 B 返回为 73–93 µs，取消到 C 完成更新为 4.910–4.912 秒，接近五秒锁等待上限。修复后八轮分别为 62–142 µs 和 257–650 µs。商品 3 的同步更新用 5.6–12.5 ms。确认 B 的订单及明细不可见、两件库存均未扣减后，从 B 的原连接池重试。从发出取消到收到重试成功用时 7.8–19.0 ms。这些是该测试的观测值。

故障代理分别在转发 `COMMIT` 前、在服务端返回成功后截断连接。两次都会在客户端得到 `CommitUnknown`。第一次原盘重启后没有订单，可用原请求号重新提交。第二次按主键、唯一索引和联接都查到同一笔订单，重复请求号被拒绝。另在服务端已确认自动提交后取消客户端上下文，库存只扣减一次。同一组测试里，96 条真实 TCP 连接在发送最后一条建表请求后关闭写方向，每条均先读到成功回包，再读到 EOF。

```sh
GOWORK=off go test -race -count=3 -v ./cmd/minidbd \
  -run '^Test(Canceled|DeadlineWhileWaiting|UnknownCommit|AutocommitLost|OrderSurvivesLost|TCPHalfClose)'
```

## 当前 SQL 边界

会话执行显式事务或逐语句自动提交。执行错误会回滚显式事务并阻止后续语句转成自动提交，直到应用结束失败的事务。条件更新影响零行时由应用选择回滚。

当前切片支持整型、文本和布尔值。建表在自动提交模式下执行，主键、唯一键及普通二级索引随表声明。更新和删除需要完整主键等值条件，查询可用全表扫描、索引等值查找、过滤和内联接。外键、任意谓词更新、独立索引构建以及 SQL 方言兼容仍待验证。

TCP 服务给每个连接分配一个独立会话，Go 客户端通过标准库连接池接入。成功回包在事务发布之后发送。客户端在可能提交的请求发出后遇到传输中断时返回结果未知，保留由应用用唯一请求号核对的机会。
