# 行版本与索引

堆页保存行版本，B+ 树保存从索引键到候选版本的映射。事务管理器解释版本的可见性。索引扫描、全表扫描和联接读取同一版本时必须作出相同判断。

## 行与版本怎样定位

**建议评审的布局。** 分开保存表内稳定的行标识和物理版本地址。更新沿用行标识，插入分配新标识。版本保存创建事务、使其失效的事务及版本间的联系。物理地址可以随新版本改变。若复用页槽，须在回收旧引用后复用，或用代次识别失效地址。

| 路径 | 读取或维护的状态 |
| --- | --- |
| 按邮箱查用户 | 按规范化索引键找到候选版本，回堆表校验键和快照可见性。旧快照仍能通过旧邮箱查到旧行。 |
| 等锁后更新 | 锁键使用表和行标识。取得锁后，从该行的版本链定位当前有效版本，复查条件。 |
| 清理旧版本 | 事务管理器给出仍在使用的最旧视图。先确认版本已无人可见、执行器或等待者也不会再引用，然后清理索引引用并回收槽位。 |

**需要决定。** A 扫描到一行后等待。B 删除它，C 又插入同主键的新行。建议 A 按原行身份重查，原行已删除即跳过。C 得到新的行标识。可以用版本链追踪或单独的行头目录定位版本。应先固定上述行为，再决定是否付出维护目录的写入成本。

## 页与恢复日志的交接

堆页和索引页都带页号、校验信息和最近修改的日志位置。索引分裂涉及的页、父指针以及页分配记录必须可一起恢复到可遍历的结构。前台执行器用短时页锁修改结构，在等待业务行锁前先释放页锁。持久化和检查点顺序见[提交与恢复](recovery.md)。

**验收。** 并发读取旧邮箱、修改唯一邮箱并触发索引分裂，在页写回中途断电。重启后用主键、新旧邮箱和全表扫描交叉核对。另测删除后同键重插，分别观察旧快照、等待者和新查询的结果。

## 当前行定位

堆页和 B+ 树叶子保存在内存中。行头目录按表内稳定的行标识定位版本链。写语句先按快照选出行标识，获得锁后沿原版本链重查。原行已删除时影响零行，同键重插使用新的行标识。表级短锁保护内存中的页和索引结构，行锁等待与刷盘在表锁之外进行。目录和已提交行随检查点写入持久化页。重启从页重建索引，再重放检查点之后的 WAL。在线回收按表轮转，每 10 毫秒检查最多 128 个槽位。它摘掉版本链和各索引中的引用，再移动最后一个堆槽填空。索引候选用双向链保存，回收一个版本无需搬移热点键的整条历史。空键和空树页会被清掉，仍有键的稀疏树页留待后续合并。检查点按页号扫描，期间暂停回收和槽位移动。
