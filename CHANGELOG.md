# Changelog

Component changes are listed newest first as they land on `main`.

## Unreleased

- MiniKV separates capacity experiments by topic and links current contracts from the component guide.
- MiniDB decouples its TCP client and wire protocol from the query engine and disk storage.
- MiniKV sends values up to 512 bytes with their reply headers in one TCP write.
- MiniDB verifies unknown commit results and same-disk recovery after a simulated group sync failure.
- MiniMQ verifies ordinary publish, delivery, and acknowledgment receipts across a same-disk process restart.
- MiniDB verifies frame size limits and ordered replies across large pipelined requests and TCP half-close.
- MiniKV documents TCP completion rates, CPU cost, and memory use near the measured load limit.
- MiniMQ skips unrelated redrive scans when a subscription has no pending redrives.
- MiniMQ rebuilds pending delivery order in one heap pass when restoring a checkpoint.
- MiniKV verifies that retrying a conditional write after a lost reply preserves its original value and expiry.
- MiniDB skips index key encoding when reclaiming an old row version that can be unlinked directly.
- MiniKV retries inbound byte reservations up to sixteen times to reduce contention-induced BUSY replies.
- MiniMQ releases idle map capacity when checkpoint pruning removes the last receipt or dead letter.
- MiniMQ releases retired segment indexes after checkpoint reclamation while preserving in-flight history reads.
- MiniDB reuses a 64 KiB WAL write buffer across commit batches and writes oversized payloads directly.
- MiniMQ verifies that retrying a delayed publish after a lost reply preserves its receipt and produces one history entry across restarts.
- MiniKV returns BAD_REQUEST for an overflowing SET deadline before checking NX or shard capacity.
- MiniMQ reuses immutable dead-letter bodies during redrive while keeping each durable record self-contained.
- MiniDB allocates transaction lock state on the first grant, saving two allocations on point reads.
- MiniKV allocates connection key buffers after admission and grows them to fit the keys received.
- MiniMQ skips encoding tail segments reclaimed by the same checkpoint while preserving protected history and recovery.
- MiniDB reuses snapshot rows during projection, saving one copy per root row in single-table queries and joins.
- MiniKV reuses the connection reply buffer for short status lines, eliminating their per-response allocation.
- MiniMQ verifies lease recovery and idempotent acknowledgment retries after a lost reply and broker restart.
- MiniDB skips redundant secondary index key encoding during uniqueness checks on inserts and updates.
- MiniKV verifies that concurrent conditional refills publish one complete value and start its TTL at publication.
- MiniMQ copies checkpoint metadata maps only when entries expire, reducing allocations and partition lock time during idle maintenance.
- MiniKV verifies eviction order and write outcomes under full-cache TCP load and retains the existing bounded sort.
- MiniDB creates lock wait timers only on contention, reducing allocations in transactions that acquire row and unique-key locks.
- MiniMQ limits dead-letter page selection to the requested number of IDs, reducing allocations and time under the partition lock.
- MiniKV copies a request key only when inserting a new entry, avoiding allocations on overwrites and rejected conditional writes.
- MiniKV avoids copying long request keys during GET lookups, reducing allocations on reads.
- MiniMQ writes large WAL frames without copying their payloads while preserving the on-disk format and sync order.
- MiniDB batches checkpoint page writes to shorten commit stalls while preserving the recovery format.
- MiniKV removes the unused two-fill admission policy from the server and keeps the original comparison reproducible.
- MiniKV verifies idle connection reclamation and documents how pooled clients recover after a timeout.
- MiniMQ orders only the earliest batch of expired leases while preserving retry and dead-letter delivery order.
- MiniDB prefers fully bound non-null unique indexes for equality lookups, reducing waits on tenant-scoped queries.
- MiniKV verifies ordered pipelined responses and documents the latency tradeoff for small page reads.
- MiniDB copies only matching rows during single-table queries, reducing allocations and writer waits on selective scans.
- MiniKV verifies large GET replies under TCP backpressure and records the latency cost of vector writes.
- MiniMQ releases one extra bounded batch between maintenance ticks to shorten waits during scheduled delivery bursts.
- MiniDB stops canceled row scans at bounded intervals so writers can regain the table lock promptly.
- MiniKV documents when a near-full shard can accept a 64 KiB refill after keys expire.
- MiniDB releases locks promptly when its Go client cancels an in-flight request and preserves final replies after a TCP half-close.
- MiniKV verifies TTL visibility, overwrite safety, and conditional refills during clustered expirations.
- MiniMQ verifies that recent short tails stay inline for fast history reads across checkpoints and restarts.
- MiniDB measures foreground lock waits during version reclamation under concurrent reads and writes.
- MiniKV documents its memory limit under mixed-size writes and verifies successful and rejected requests in one workload.
- MiniKV replaces idle buffers when write sizes change so near-full caches can reuse memory across workloads.
- MiniDB reclaims row and index versions between active statement snapshots during long-running queries.
- MiniMQ assembles message frames directly in sealed segments to reduce checkpoint copying and allocations.
- MiniKV measures same-shard and cross-shard read latency during large overwrites.
- MiniMQ batches directory syncs for new checkpoint files before publishing the durable checkpoint head.
- MiniDB shares its MVCC cleanup budget across tables so quiet tables do not delay reclamation on busy ones.
- MiniKV reuses receive buffers for nearby large write sizes to reduce memory pressure when a full cache rejects writes.
- MiniMQ reads sealed message bodies from disk on demand and protects active history reads during segment reclamation.
- MiniDB reclaims obsolete row and index versions online and coalesces commits queued during a WAL flush.
- MiniKV documents latency and memory use under mixed workloads with a reproducible Redis comparison.
- MiniMQ supports durable single-partition messaging with delayed delivery, acknowledgments, and dead-letter redrive.
- MiniDB supports concurrent Read Committed transactions and recovers committed data from checkpoints and the write-ahead log.
- MiniKV serves a sharded in-memory cache over TCP with per-key expiry and bounded eviction.
