# 任务订阅与确认

订阅按分区保存连续结案边界、边界之后的有限位点窗口及活跃任务明细。订阅注册也占用分区提交序列中的位置。受理时确定的订阅集合决定归属。延迟消息到期时仍按原集合交付。

| 事件 | 条件和更新 |
| --- | --- |
| 拉取 | 在条数、字节和窗口跨度限制内选可领取项。提交新代次、worker 身份和截止时间后发出正文。回包丢失也计一次已授予领取。 |
| ACK | 先查同凭证的成功回执，再核对当前任务实例、代次、身份和有效期。有效则结案并记回执。过期凭证不改变新领取。 |
| 失败或超时 | 在提交序列中只裁决一次。记录下次可领时间或转入待转死信。到期扫描和客户端失败报告使用同一任务代次，过时代次无法重复推进。 |
| 转入死信 | 原任务继续占用保护额度，直到可独立取回的死信与原任务结案共同提交。 |

例如 418 正在退避，419 至 425 已确认。窗口保存这些后续结案记录。重启后可以继续推进，不能据此丢弃 418。窗口跨度耗尽时只暂停本订阅更远的领取。普通消息的业务完成顺序可以与位点顺序不同。

**凭证与业务结果。** 对外需要区别“本次已确认”“此前已确认”“凭证已过期”和“回执已过期、结果未知”。broker 只裁决订阅状态。若 worker 已发送通知但 ACK 丢失，业务仍可能重复执行，幂等键应随消息一起传给下游。

**验收。** 让旧 worker 的首次 ACK 与另一个 worker 的重新领取竞争。再让一次有效 ACK 仅丢失回包。前者不得改变新领取，后者须在回执期内返回原结果。切换或重启后用同一组凭证重复核对。
