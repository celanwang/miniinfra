# 分区日志与受理

分区为本地命令排出提交顺序。命令序号标识一次状态转换，历史位点只分配给已经发布的消息。领取、ACK 或死信转换会推进命令序号，历史读者的下一位点保持原义。

| 输入 | 同一次提交中记录 | 向调用方返回 |
| --- | --- | --- |
| 普通发布 | 消息 ID、正文、受理时的订阅集合或可恢复的订阅版本、历史位点、去重回执。 | 已提交且已应用后返回分区和位点。 |
| 延迟发布 | 消息 ID、正文、最早发布时间、受保护订阅和去重回执。 | 已调度及分区。到期发布另行分配位点。 |
| 相同请求重试 | 在去重期内查原回执，比较请求内容和投递条件。 | 相同时返回原结果，冲突时返回错误。 |
| 历史读取 | 定位已提交可读区间，取得短时段引用。 | 返回消息批次及下一位点。落后于可读起点时返回缺口。 |

请求映射到相同分区是本地去重成立的条件。建议在发布接口明确去重作用域和稳定的路由输入。同一消息 ID 改用其他路由键时，分区内的回执无法承担全局唯一性。恢复期间也要保留仍在有效期内的回执。

## 磁盘回收

段文件按分区位点排序。启动逐帧校验封存段，复用帧与解码缓冲区，每条消息只保留文件位置、正文长度和受理序号。回读先定位段，再直接读取指定帧。可回收段必须已封存、超过历史保留期、所有受保护订阅都已结案，并释放在途读取引用。先持久化新起点与清单，再删除旧段。重放时已删除段不能重新变成可读历史。

准入按存储卷核算。先扣除存量任务剩余领取与结案、每个订阅潜在的死信正文、延迟发布和检查点切换的峰值空间，再决定是否接收新写入。应能分别观测物理空闲空间、已承诺空间、阻塞回收的订阅和段。共享卷上的分区共同遵守卷预算。文件系统实际写入失败时保持最后一个已提交结果。

**验收。** 一个离线订阅钉住旧段，另一个订阅继续 ACK。在准入拒绝新消息后完成已有任务的死信转换，取回正文并核对可读起点。额外模拟设备写入失败，恢复后核对已经返回成功的记录。

单分区基线在检查点封存达到条数上限的段，未满的短尾随检查点保存。短尾全部达到历史保留期后也会封存，低频流量因此可以回收最后一段。历史回读在分区锁内按条数和字节选取一页，在锁外读取正文。同一分区同时读取一页，每页最多打开一个段文件。回收只推进到在途页起点所在的段之前，下一次检查点可以再次尝试。领取和最终转死信仍在分区锁内读取已选正文，沿用原有提交顺序。检查点期间仍暂停分区写入。逻辑配额为现有状态、收尾和检查点留空间，并检查实际卷余量。该基线依赖独占存储预算，多个进程共享该卷时需要部署方隔离配额。
