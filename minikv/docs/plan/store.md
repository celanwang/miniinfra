# 分片存储与单键操作

同一个键始终路由到同一个分片。分片拥有键索引、紧凑条目数组、条目额度和写入顺序。每个条目记录不可变值及截止时间。一次请求的状态在分片锁内裁决，网络传输在锁外完成。

`GET` 在同步查找期间借用连接的帧内键缓冲。路由用 `maphash.Bytes`，与写入对同样字节使用相同种子和分片计算。字符串转换直接放在索引查找表达式里，让 Go 复用现有键字节。写入仍生成独立的字符串键，连接可以在下一帧覆盖接收缓冲。[长键分配与 TCP 对照](capacity.md#热-get-的键查找) · [Go `maphash`](https://pkg.go.dev/hash/maphash) · [Go 字符串查找转换](https://github.com/golang/go/blob/go1.27.3/src/runtime/string.go#L183)

| 操作 | 锁内步骤 | 可观察结果 |
| --- | --- | --- |
| 读取 | 查槽位，读取单调时钟并比较截止时间。对有效值尝试预留出站额度。 | 已过期返回未命中，额度不足返回过载，成功则返回选中的完整值。 |
| 仅在缺失时写入 | 同时检查键和当前截止时间。存在有效值时保留原值。缺失或已到期时执行与普通写入相同的容量检查。 | 返回已存在、已写入或明确拒绝。 |
| 写入或覆盖 | 校验参数后预备新值，持写锁计算净增量和可回收候选，再原子应用淘汰、值和新截止时间。 | 被拒绝时原条目、原 TTL 和其他候选均保持本次写前的状态。 |
| 后台过期 | 在写锁内复查槽位当前条目的截止时间，再删除。 | 已续期或替换的值不会被旧扫描记录误删。 |

删除通过末尾条目填补空槽，更新被移动键的索引，再清空末尾引用。批量淘汰可以保存候选键并在提交时重新定位，也可以按安全顺序处理槽位，避免一次交换删除改变剩余候选的身份。后台扫描遇到被移入的条目可在本批剩余预算内复查，也可留给下一轮。读取始终按实际截止时间判断。

**接口边界。** TTL 从成功发布起算。线协议使用正整数毫秒或显式的 `NONE`。零、负数和溢出返回参数错误。分片接收已规范化的时长，并在发布前检查单调时钟截止时间是否溢出。

**验收。** 写入刚好到期时，普通读取应未命中，条件写可以接纳新值。一次覆盖需要淘汰两个条目而只找到一个时，应整体拒绝。检查目标和两个候选的值及 TTL 均未改变。再对一个分片批量淘汰多个槽位，逐键核对索引映射。
