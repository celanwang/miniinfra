# 连接与在途额度

连接层拥有请求解析缓冲、在途额度和发送中的值引用。每条连接串行处理请求。额度同时受单连接和全实例限制。分片只需要知道本次值引用能否交给发送方。

## 一次请求占住哪些资源

1. 从受限的小缓冲读取请求头，校验声明的键和值长度，再预留入站额度。读取请求头前设定覆盖头和请求体的同一截止时间。对已拒绝且有未读请求体的帧，发送允许的小错误响应后关闭连接，避免将残余字节解析成下一帧。
2. 缓冲准备完成后，存储层在分片锁内裁决写入。成功时先将新缓冲记入条目额度，再移交所有权并释放入站额度。请求超时、断开或写入未提交时，归还入站额度，未发布的缓冲交由接收层回收。
3. 读取命中时，在释放分片读锁前尝试预留发送所需额度。额度立即尝试，分片锁内的原子重试次数有上限。申请失败便释放锁并返回过载。发送线程持有不可变值。响应发完、失败或达到整次发送的期限后，释放引用和额度。

值的在途额度按底层缓冲容量计费，键的入站额度按帧声明的长度计费。一个共享值交给多个响应时，每个响应分别预留，便于值被淘汰后仍限制最坏占用。发送过程可以部分成功。连接关闭后客户端丢弃不完整响应。写请求已提交但回包丢失时，客户端看到结果未知。额度拒绝应有独立结果，让调用方能够把过载与缓存缺失区分开。 [Go 连接读写期限](https://pkg.go.dev/net#Conn)

## 连接保留的键缓冲

连接在读到合法帧头并预留入站额度后才准备键缓冲。第一次按实际键长分配，起步容量为 128 B 或配置上限中的较小值。更长的键需要更大的缓冲时按本次键长替换，后续短键继续复用。连接在关闭前保留用到的最大容量，计入进程堆预算。发布的键仍由存储层持有独立字符串。

用 32 条真实 TCP 连接，比较 `61e2872` 和按需分配。每组从全部连接已开始等待请求但还未收到帧开始，随后全部读 1 B 键、其中 4 条读一次上限长度的键后全部回到短键，最后全部重复读上限长度的键。每个阶段用 GC 后的 `HeapAlloc` 减去连接建立前的基准再除以连接数。样本包含同进程客户端和测试连接的开销。Linux arm64、Go 1.27.3，两个版本在 CPU 6–7 串行交错，容器上限 160 MiB。

| 键长上限 | 空闲 B / 连接 | 只读短键 | 偶尔长键后 | 持续长键后 |
| --- | ---: | ---: | ---: | ---: |
| 1 KiB | 3,366 / 2,337 | 3,380 / 2,485 | 3,383 / 2,628 | 3,383 / 3,396 |
| 64 KiB | 67,600 / 1,847 | 67,592 / 1,975 | 67,592 / 10,151 | 67,592 / 67,383 |

表中为基线 / 按需的三轮中位数。64 KiB 上限时，短键组的堆增量减少约 97%，4 条连接用过长键的组减少约 85%。每条连接都用过上限长度时，两版保留量接近。

单连接预热后连续 GET 做五对 TCP 测量，双方四种配置均显示 0 B/请求、0 次分配。1 KiB 上限下，读短键的中位数为 3.46 / 3.40 µs，读 1 KiB 键为 3.66 / 3.66 µs。64 KiB 上限下，读短键为 3.38 / 3.46 µs，读 64 KiB 键为 13.57 / 13.48 µs。配对差异都在 4% 以内。采用依据是空闲和短键连接的堆收益。TCP 回归覆盖上限长度二进制键、短长键管线切换、重连后读回已发布的键、超限关闭以及部分长键归还入站额度。

从组件目录用同一基准代码复跑，比较基线和当前版本。

```sh
base=$(mktemp -d)
git -C .. archive 61e2872 minikv | tar -x -C "$base"
cp internal/server/key_buffer_bench_test.go "$base/minikv/internal/server/"
for peer in "$base/minikv" "$PWD"; do
    GOWORK=off GOMAXPROCS=2 go test -C "$peer" -run '^$' -bench '^BenchmarkTCPKeyBufferPool$' -benchtime=1x -count=3 ./internal/server
    GOWORK=off GOMAXPROCS=2 go test -C "$peer" -run '^$' -bench '^BenchmarkTCPKeyBufferGET$' -benchmem -benchtime=300ms -count=5 ./internal/server
done
```

## 大值接收缓冲

64 KiB 及以上的大值可按 4 KiB 向上取整后接收，入站额度按实际缓冲容量申请。取整后超出单值限制、池上限或可用入站额度时，使用精确长度。值体完整读入后，分片裁决写入。精确容量的缓冲可以直接移交给条目，取整缓冲只有在通过容量和准入检查后才在写锁内复制出精确容量的发布值。失败或未读完的缓冲可以回到池中，下次使用会完整覆盖本次值体。返回 `NO_SPACE` 时整个值体已经消耗，同一连接可继续处理下一帧。

空闲缓冲总量限制为 8 MiB 和实例入站额度一半中的较小值，单独计入进程预算。小值读写绕过缓冲池，大值写按接收容量复用。归还缓冲需要腾出空间时，按归还时间从最早的空闲缓冲开始移除，直到新缓冲可容纳。只替换空闲缓冲，活动请求的额度和已发布的值各自管理。成功取整写的临时接收缓冲和发布值会同时占用内存。[跨尺寸切换对照](capacity.md#空闲池跨尺寸切换)[近满写入并发小读实测](capacity.md#近满写入并发小读)

## 验收

- 在发送器取走值引用后暂停它，淘汰该键。新读取未命中，旧响应仍能完整发送。释放发生在发送结束或超时。
- 请求头已声明一个大值，客户端只发送部分数据。接收截止后入站额度应完全归还，原值保持可读。
- 用尽出站额度后，另一个分片仍能完成写入。额度归还后读取可恢复。分别记录容量拒绝、网络超时和缓存未命中次数。
