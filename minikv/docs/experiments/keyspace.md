# 分片存储实验

用于核对热读的键查找、发布时的键复制和满分片淘汰。实现规则见[分片存储与单键操作](../plan/store.md)，命令从组件目录运行，公共配置见[环境与口径](../plan/capacity.md#环境与口径)。

## 热 GET 的键查找

用 Go 1.27.3，在服务端复用读帧和键缓冲，按键长各跑 1000 次命中和未命中。计量覆盖读入键、路由、查索引和预留命中值的出站额度。基线是 `68136d8`，在调用 Store 前先把键转换成字符串。借用版直接对字节哈希，并在字符串索引的查找表达式里转换。

| 键长 | 基线分配次数 / 请求，命中与未命中 | 借用版分配次数 / 请求，命中与未命中 |
| --- | ---: | ---: |
| 16、32 B | 0 | 0 |
| 33、64、128、256、1024 B | 1 | 0 |

沿用页读取回放，以窗口 1、每秒 1,250 页和另 10,000 次单次 GET 读 512 B 值。以 16 B 和 64 B 命名空间键各做三对，双方运行同一个 Linux arm64 发压器，每轮 6 秒，每对交换顺序。服务和驱动分别固定 CPU 0–1 和 2–5，容器上限 160 MiB。页内容逐个验对，`/runtime` 在预热后和读完后采样，堆分配量与 cgroup CPU 除以成功 GET 数。两个快照包含诊断本身的少量开销。

| 键长 | 服务堆分配 B / GET | 窗口内 GC 次数 | 服务 CPU µs / GET | 单次 GET 在线 P99 | 单次 GET RTT P99 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 16 B | 0.02 / 0.00 | 0 / 0 | 4.34 / 4.28 | 3.88 / 3.89 ms | 1.51 / 1.50 ms |
| 64 B | 65.05 / 0.02 | 2 / 0 | 4.49 / 4.37 | 3.93 / 3.89 ms | 1.61 / 1.51 ms |

表中为基线 / 借用版的三轮中位数。所有已发送请求均成功，计划总完成率最低为 99.93%。64 B 每对的服务 CPU 降幅为 0.4%–16.1%，单次 GET RTT P99 差为 +0.002、−0.032、−0.540 ms，整页在线 P99 差为 −0.028、+0.691、−2.761 ms。堆分配下降和窗口内 GC 减少在三对都复现，TCP 尾延迟的变化随轮次而异。

**保留帧内借用。** 在原有查找路径消除长键的临时分配。真实 TCP 回归覆盖不同分片上的短键和 1024 B 二进制键、长键未命中与 `SET NX`、以及并发覆盖时已开始发送的旧值仍完整。接收路径的命中与未命中分配是单独测量的，表中端到端回放为已预热的命中负载。

从组件目录复跑，每对可以交换两个 peer 的顺序。

```sh
base=$(mktemp -d)
git -C .. archive 68136d8 minikv | tar -x -C "$base"
for size in 16 64; do
    for peer in "$base/minikv" "$PWD"; do
        GOWORK=off python3 experiments/capacity.py --profiles page --rates 1250 \
            --page-window 1 --page-key-bytes "$size" --tick 250us \
            --server-cpus 0-1 --driver-cpus 2-5 --peer-module "$peer"
    done
done
```

## SET 的键复制

基线 `7be8b07` 在接收后将每个 SET 的键转成字符串。借用版在锁内用帧内键找槽，沿用已有条目的字符串，成功发布新键时才复制。两条路径都在裁决前读完值体。容量检查按键字节加发布值的容量计算，覆盖再扣除原条目记账。

在 Go 1.27.3 上用复用的键缓冲和收帧读取器调用同一服务端接收路径。对 16、64、256 B 键，分别以空值和 16 B 值测 1,000 次。首次插入用单槽里两键交替，每次都是当前缺失的键。下表覆盖读键、读值和存储判定，响应发送另在 TCP 回放中测量。

| 操作 | 空值分配次数，基线 / 借用 | 16 B 值分配次数，基线 / 借用 |
| --- | ---: | ---: |
| 覆盖已有键 | 1 / 0 | 2 / 1 |
| `SET NX` 返回 `EXISTS` | 1 / 0 | 2 / 1 |
| 首次写入缺失键 | 1 / 1 | 2 / 2 |

复用 `small` TCP 回放预填 512 B 小值后混合 GET 与覆盖 SET，键长 11 B。每轮计划每秒 30,000 次普通请求，另有 40 次背景请求，约 5% 是覆盖。Linux arm64，同一驱动、250 µs 节拍、每轮 6 秒。双方服务固定 CPU 0–1，驱动固定 CPU 2–5，服务容器上限 160 MiB。三对串行交换顺序。预填后和结束时采集 `/runtime`，按成功请求数或成功 SET 数归一堆分配差额，计入本轮整个服务进程的分配。

| 指标，三轮中位数 | 基线 | 借用 |
| --- | ---: | ---: |
| 服务堆分配 B / 成功请求 | 26.77 | 25.97 |
| 服务堆分配 B / 成功 SET | 535.09 | 519.08 |
| 服务 CPU µs / 成功请求 | 3.37 | 3.39 |
| 小 GET 在线 P99 | 3.99 ms | 4.03 ms |
| 小 GET RTT P99 | 0.99 ms | 1.10 ms |

每轮成功覆盖 9,011–9,019 次，已发请求全成功，计划完成率最低 99.92%。每对按成功 SET 数归一的堆分配少了 15.0–16.9 B，接近 11 B 键的原分配规格 16 B；此口径还包含值缓冲和响应等服务开销。CPU 与尾延迟的配对结果有升有降。六轮窗口都没有 GC 周期。

**保留只在插入时复制键。** 它在单一写入路径上减少已存在键的分配，混合回放复现了这个成本差。真实 TCP 回归覆盖跨分片的短键和 1024 B 二进制键、覆盖后重连读回、`NX` 拒绝、容量拒绝后原值仍按原 TTL 到期，以及并发覆盖时在途旧值不变。

```sh
base=$(mktemp -d)
git -C .. archive 7be8b07 minikv | tar -x -C "$base"
for peer in "$base/minikv" "$PWD"; do
    GOWORK=off python3 experiments/capacity.py --profiles small --rates 30000 \
        --tick 250us --server-cpus 0-1 --driver-cpus 2-5 --peer-module "$peer"
done
```

从组件目录运行，每对可交换两个 peer 的顺序。比较输出中 `Engine` 为 `minikv` 的行。

## 满载插入的单个淘汰候选

基线 `26689fb` 对有界样本排序，再取刚好补足槽位和字节的前缀。候选先按同一个比较器线性寻找首选条目。若首选能腾出所需空间，直接返回它，否则对完整样本排序并取原前缀。确定性用例两版均通过，覆盖环绕采样、过期优先、写入顺序、排除覆盖目标、多个候选刚好补足、失败和游标推进。

TCP 回放将 16 个分片各填到 4096 槽和 4 MiB。旧条目记账 912 B，9 B 键、903 B 值，均有效。8 条写连接各在不同分片按固定节拍插入 192 个新键。先做 120 次同尺寸插入，使每次都在满槽时回收一项。随后交错做 48 次需回收两项的插入与 24 次需回收十七项的尝试。样本上限为 16，采样窗在这轮里不绕回已移动的尾部条目。用分片计数核对真实淘汰量，并按组统计完整 SET 响应的 RTT。16 条读连接以 10k/s 计划发压，其中一半与写入同分片，热点槽位在采样覆盖区之外。写入约每毫秒四笔，读延迟按写入窗口统计。

同一 Linux arm64 驱动和 160 MiB 上限，服务固定 CPU 0–1，驱动固定 CPU 2–5，三对交换先后。采用条件是单候选写入在至少两对的 P50 同时改善 10% 和 2 µs，或 P99 同时改善 10% 和 50 µs，并维持并发读、回退写入和拒绝的表现。初次突发回放验证了各类容量结果，正式对照按固定节拍发写，以取得更充足的同分片读样本。

隔离的 Go 1.27.3 规划基准在 macOS arm64 上固定 4096 槽、每次采 16 个，包含过期和活项，每组五轮。中位数为下表，两种实现的三类路径都为 0 分配。

| 规划结果 | 排序基线 | 先选首项 |
| --- | ---: | ---: |
| 单项够用 | 180.8 ns | 41.3 ns |
| 需两项 | 180.2 ns | 211.1 ns |
| 拒绝 | 188.2 ns | 217.1 ns |

TCP 六轮均返回 1,344 次 `STORED` 和 192 次 `NO_SPACE`，与每轮 1,728 次活键淘汰相符。960 次满槽单项占全部尝试的 62.5%，占成功写入的 71.4%。其余为 384 次双项和 192 次拒绝。这个占比由回放设定。八条写连接都能继续读，已发 GET 全部命中，读计划完成率最低 99.79%。每轮写入窗口约 384–389 ms，其中约 1,900 次 GET 与写入同分片。

| TCP 指标，三轮中位数 | 排序基线 | 先选首项 |
| --- | ---: | ---: |
| 单项 SET RTT P50 / P99 | 40.25 / 276.82 µs | 44.37 / 1,010.07 µs |
| 双项 SET RTT P50 / P99 | 45.87 / 1,026.02 µs | 46.37 / 4,176.67 µs |
| 拒绝 SET RTT P50 / P99 | 53.66 / 1,035.98 µs | 57.00 / 2,860.92 µs |
| 同分片 GET 在线 / RTT P99 | 4.47 / 1.48 ms | 5.98 / 2.68 ms |
| 跨分片 GET 在线 / RTT P99 | 4.47 / 1.72 ms | 6.24 / 2.69 ms |

**保留现有排序。** 单项 SET P50 在三对均增加 4.1–5.4 µs，P99 仅一对减少 31.6 µs。局部单项规划的节省达到了纳秒级收益，回退到排序的两条路径多一次扫描。满载 TCP 结果未达到采用条件。候选以补丁保留供复跑。

```sh
peers=$(mktemp -d)
for arm in baseline single; do
    mkdir "$peers/$arm"
    git -C .. archive 26689fb minikv | tar -x -C "$peers/$arm"
    cp internal/store/plan_test.go "$peers/$arm/minikv/internal/store/"
done
git -C "$peers/single" apply --unidiff-zero "$PWD/experiments/single-victim.patch"
for arm in baseline single; do
    GOWORK=off GOMAXPROCS=1 go test -C "$peers/$arm/minikv" -run '^TestPlanPreservesSampleOrderAndPrefix$' \
        -bench '^BenchmarkPlanFullShard' -benchmem -benchtime=250ms -count=5 ./internal/store
    GOWORK=off python3 experiments/capacity.py --profiles pressure --pressure-lengths eviction \
        --server-cpus 0-1 --driver-cpus 2-5 --peer-module "$peers/$arm/minikv"
done
```
